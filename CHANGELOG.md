## Unreleased

### ⚠ Breaking and behaviour changes

* **Schedule of ordered steps instead of middleware chains.** Each stage is now an ordered list of steps built from a `ScheduleModel` (new, `IIonApplication.Schedule` / `ISceneBuilder.Schedule`) when the game loop is built: a step is a public `void M(GameTime dt)` (or `void M()`, or `void M(GameTime dt, TService s, ...)` with services resolved once) marked with a stage attribute, and runs and returns. Steps run by the new `Order` property of the stage attributes (default 0), then registration order, then declaration order; `[After<T>]`/`[Before<T>]` (new generic attributes, method or class level) take precedence. Wrapping is expressed with `[Begin(Stage.X)]`/`[End(Stage.X)]` scope pairs, whose end runs in a `finally`. New `Stage` enum (values match `GameLoopStage`) and `StageOrder` constants.
* **Registration order no longer matters.** Engine steps use reserved order bands (`-1000..-500` setup, `500..1000` teardown), so user steps at the default order run between them whether registered before or after `UseIon()`. Every engine system is now leaf steps and scopes: `EventSystem` (Last, 1000), `TraceTimerSystem` (a scope at -1000 on every stage but FixedUpdate; `UseDebugUtils()` adds nothing in Release builds of the package), `WindowSystem` and `NullWindowSystem` (Init/First -950, close check in Render at 900), `InputSystem`/`NullInputSystem` (First -940), `GraphicsSystem` (Init and a Render frame scope at -900), `AudioSystem` (Init and Last -880, Destroy 880), `SpriteBatchSystem`/`NullSpriteBatchSystem` (Init and a Render scope at -850), `CoroutineSystem` (Update -600) and `SceneSystem` (-500 in every stage).
* **Scenes.** `SceneSystem` is public and runs the active scene's own `Schedule` as one step per stage, so scene systems follow the same ordering rules; systems registered after `UseScene` are no longer affected by its position. `SceneInstance` exposes `Schedule` and its stage delegates are read-only. Scene schedules are planned (validated) when the application's schedule is built, with a temporary scope, so a scene's configure callback runs once more at build time. Registering on a scene builder after the scene loaded throws `ION004`.
* **Validation at build.** `IonApplication.Build()` throws `IonScheduleException` (with `Diagnostics` and `Codes`) listing every error: `ION001` unknown stage, `ION002` Before/After cycle, `ION003` unpaired scope, `ION004` stage attribute on a non-public method, `ION005` async/`Task` step, `ION006` scoped system or scoped step parameter in the root schedule, `ION007` unsupported signature, `ION008` unregistered parameter, `ION009` unregistered system, `ION011` ambiguous scope. Methods with unsupported signatures used to be logged and skipped. Warnings `ION010` (legacy middleware), `ION012` (constraint on a system not in the schedule) and `ION013` (system without steps) are logged once under `Ion.Schedule`. The Breakout ECS sample's systems are now singletons (they were scoped but resolved from the root).
* **Legacy middleware.** `(GameTime dt, GameLoopDelegate next)` and `GameLoopDelegate (GameLoopDelegate next)` methods, `UseInit(...)`..`UseDestroy(...)` delegates and the generated `Use{Stage}<TService...>` overloads keep working as opaque middleware placed by their order (order 0 for the delegates), wrapping the steps after them, with warning `ION010`.
* **Scene enum overloads are library methods.** `UseScene(Scene.X, ...)` and `EmitChangeScene(Scene.X)` are now the generic `UseScene<TScene>` and `EmitChangeScene<TScene>` (`where TScene : struct, Enum`) of `Ion.Extensions.Scenes`; the scenes generator only emits the `[ScenesEnum]` attribute. Call sites compile unchanged. (Generators cannot see each other's output, so the schedule generator could not bind scene registrations made through a generated overload.)
* **Clean stack traces.** `GameLoop.Run`/`RunFrames`/`Step`/`Initialize`/`Shutdown`, `IonApplication.Run`/`RunFrames` and the scene system's dispatch steps are `[StackTraceHidden]`, like the runtime schedule runners and the new step adapters, so an exception thrown by a step shows the step, then the caller of `Run` (for example `Program.<Main>$`).
* **Removed:** `MiddlewarePipelineBuilder`, `IMiddlewarePipelineBuilder`, `SystemMiddlewareBinder.TryGetSystemFunction` (the class keeps the `MiddlewareAccessibility` constant, which now includes non-public methods), and `GameLoop.InitBuilder`..`DestroyBuilder`; `GameLoop` gains `Schedule`, `ScheduleFactory` and `UseSchedule(Schedule)`, and `GameLoop.Build()` rebuilds from the factory (hot reload). The stage attributes are sealed and derive from the new `StageAttribute`. `IonTestHost` polls its event collectors from a Last step at order 990 (`IonTestHost.CollectorOrder`), so events emitted by Last steps at lower orders are collected the same frame.

* **.NET 10.** Every engine, test, benchmark and sample project targets `net10.0` and the repository builds with the .NET 10 SDK (`global.json`: `10.0.100`, `rollForward: latestFeature`, C# `latest`). Source generators stay `netstandard2.0` on Roslyn 4.4. `Microsoft.Extensions.*` packages move to 10.0.x.
* **User data folder.** `IPersistentStorage.User` (and `Saves` under it) now lives in a per-game folder named after `GameConfig.Title` under the user's local application data folder in every build configuration (it was the working directory in Debug builds). Game content and assets are resolved from `AppContext.BaseDirectory` instead of the working directory. All three can be overridden with the new `Ion:Storage` section (`StorageConfig.GamePath`, `AssetsPath`, `UserPath`). `OpenWrite` now truncates existing files.
* **Asset caching.** `IBaseAssetManager.GetOrLoad(path, load)` caches assets by (type, path) and returns the same instance on repeated loads; scene-scoped asset managers own and dispose what they load. `Load<SoundEffect>`, `Load<Texture2D>` and `Load<FontSet>` all go through it (font sets are keyed by their name). Reloading a texture that was disposed directly loads it again.
* **Coroutines.** `CoroutineRunner` moved from the `Ion` namespace to `Ion.Extensions.Coroutines`. `ICoroutineRunner` is a singleton (it was transient, so every consumer had its own runner), and `UseCoroutines()` adds a `CoroutineSystem` that steps it in the Update stage; `UseIon()` now calls `UseCoroutines()`. `Stop` of an unknown or finished routine is a no-op. `CoroutineRunner` takes `IEvents` instead of `IServiceProvider` (each coroutine reads events through its own `EventReaderSet`, see Events v2), and is `IDisposable`.
* **Events v2: `IEvent` removed, `IEventEmitter`/`IEventListener` obsolete.** The boxed `RingBuffer<IEvent>` bus is replaced by unboxed per-type channels (`IEvents`, `EventBus`, `EventChannel<T>`, `EventReader<T>`, see Features). `IEvent`, `IEvent<T>`, `Handled` (it was never set), `EventId` and the type-hash `EventType` are removed. `IEventEmitter`, `IEventListener`, `IEventListenerFactory`, `EventEmitter` and `EventListener` are `[Obsolete]` adapters over `IEvents` for one release: `IEventListener.On<T>(out T)` and `OnLatest<T>(out T)` now return the event itself (was `IEvent<T>` with `.Data`), `EventEmitter` wraps an `IEvents` (its frame buffers, `Step` semantics aside, are gone), `EventListener` takes an `IEvents` and `Dispose` is a no-op. Engine code, `Ion.Testing` and the samples use `IEvents`: `GameLoop` and `EventSystem` take the `EventBus`; `SceneSystem`, the window, input and graphics systems, `AssetReloadSystem` and `CoroutineRunner` take `IEvents`; `EmitChangeScene` extends `IEvents` (the `IEventEmitter` overloads are obsolete); `IWait.Update` and `Wait.PollEvent` take the coroutine's `EventReaderSet` instead of an `IEventListener`; `IonTestHost.Events` is `IEvents`. A reader created by `IEvents.Reader<T>()` starts at the oldest visible event, like a new listener did.
* **Graphics configuration.** `GraphicsConfig.ClearColorHex` binds the clear color from configuration (`Ion:Graphics:ClearColorHex`, `RGB`/`RGBA`/`RRGGBB`/`RRGGBBAA`). `WindowConfig` is now bound from `Ion:Window` (it was ignored).
* **Graphics backend mapping.** `GraphicsConfig.PreferredBackend` is mapped explicitly onto Veldrid's backends (the old enum cast was off by one: Vulkan selected OpenGL, OpenGL selected Metal). Unsupported backends fall back to the platform default with a warning; `Direct3D12` and `WebGPU` throw `NotSupportedException`.
* **Injectable clock.** `GameLoop` takes an `IClock` (new in `Ion.Core.Abstractions`: `Elapsed`, `Seconds`, `NextFrame()`, `Sleep(TimeSpan)`) instead of owning a `Stopwatch`. `Ion.Core` ships `StopwatchClock` (registered by default), `FixedStepClock(TimeSpan step)` (every frame lasts exactly one step, sleeps never block) and `ManualClock` (test-controlled `Advance(TimeSpan)`, records sleep requests). Register another `IClock` to replace the default.
* **Fixed step decoupled from MaxFPS.** `FixedGameTime.Delta` is now `1 / GameConfig.FixedUpdateRate` (new, Hz, default 60) instead of `1 / MaxFPS`. `MaxFPS` only paces rendering, and `0` (or any value below 1) now means uncapped (it used to mean 120). The 100 ms frame clamp is configurable through `GameConfig.MaxFrameTime`. `FixedGameTime.Elapsed` is the simulated time (the sum of fixed steps run) rather than the frame's wall time. New `GameConfig.VSync` turns off the loop's own pacing so the graphics layer can pace on present.
* **Frame pacing.** The end-of-frame wait sleeps for the bulk of the remaining time and spins the last millisecond, and raises the Windows timer resolution to 1 ms (`timeBeginPeriod`) while the loop runs. No pacing happens when `VSync` is set.
* **Run and step API.** `GameLoop.Run(CancellationToken = default)`, `GameLoop.RunFrames(int)` and a parameterless `GameLoop.Step()` that runs one complete timed frame (accumulator, fixed steps, pacing); `Step(GameTime)` is unchanged. `IIonApplication`/`IonApplication` gain `Run(CancellationToken)` and `RunFrames(int)`. `GameLoop.Run` throws `InvalidOperationException` if the loop is already running.
* **Substitutable events and tracing.** The container registers the concrete `EventBus` and forwards `IEvents` to it, so a fake `IEvents` can be registered without breaking the engine's own plumbing (the loop's fixed-step marks and `EventSystem` keep using the bus). `ITraceManager` gains `CreateTimer(string prefix)`; `TraceTimer` and `TraceTimerSystem` no longer downcast to the internal `TraceManager`, so a fake `ITraceManager` can be injected.
* **Asset types as abstractions.** Games depend on `ITexture2D`, `IFontSet`, `IFont` and `ISoundEffect` and load them with the new `IBaseAssetManager.Load<T>(path)`, which looks up the loader registered for `typeof(T)` through the new `IAssetLoader<T>` and caches like `GetOrLoad`. Loaders are now registered under the interface type (`IAssetLoader.AssetType == typeof(ITexture2D)` etc.). `IFontSet.CreateStyle(size)` returns `IFont`; `IFontSetLoader` and `LoadFontSet(name, params fonts)` combine several font files. `Load<Texture2D>`/`Load<SoundEffect>` written as instance calls now bind to `Load<T>` and return the same cached asset.
* **Obsolete for one release:** the concrete `Texture2D`, `BaseTexture`, `FontSet`, `Font` (Veldrid) and `SoundEffect` (NAudio) types and their `Load<T>` extension methods (`Texture2DAssetManagerExtensions`, `FontAssetManagerExtensions`, `SoundEffectAssetManagerExtensions`), which forward to the new API. `FontLoader`, `SoundEffectLoader`, `AudioManager`, `TextureFactoryExtensions` and the Veldrid and audio systems (`WindowSystem`, `InputSystem`, `GraphicsSystem`, `SpriteBatchSystem`, `AudioSystem`) are now internal.
* **No interface downcasts.** The Veldrid backend registers `Window`, `GraphicsContext`, `SpriteBatch` and `InputState` as themselves and forwards `IWindow`, `IGraphicsContext`, `ISpriteBatch` and `IInputState` to them; engine systems depend on the concrete types, so tests can replace the interfaces with fakes. `AddAudio()` does the same for `IAudioManager`.
* **Input and events in fixed steps.** `IInputState` edges and deltas now depend on the stage that reads them: from `FixedUpdate` they cover everything since the previous fixed step, so an edge is seen by exactly one fixed step whatever the ratio of `MaxFPS` to `FixedUpdateRate` (at 120 fps and 60 Hz about every other frame runs no fixed step, and clicks on those frames were lost, which stopped the Breakout ECS paddle from launching balls). Every other stage keeps the per-frame view. `IInputState` gains `MouseDelta`. Events that leave the two-frame window before any fixed step has run since they were emitted are kept in a fixed-step backlog and delivered to readers in `FixedUpdate` (at most `EventBus.MaxBacklogFrames` frames); other stages see the same two-frame window as before.
* **Loop context.** New `ILoopContext` (`Stage`, `Frame`, `FixedStepCount`) and `GameLoopStage` in `Ion.Core.Abstractions`; `GameLoopContext` is registered by `IonApplication.CreateBuilder` and kept up to date by `GameLoop` (exposed as `GameLoop.Context`). `GameLoop` gains `Initialize()`, `Shutdown()` and `IsExitRequested` for hosts that drive frames with `Step()`.
* **Audio rewritten (no NAudio).** The DirectSound (NAudio) backend is gone; audio is an engine mixer with an OpenAL output (see Features). `IAudioManager.Play(sound, volume, pitchShift)` keeps its first three parameters and gains `pan`, `loop`, `bus` and `fadeIn`; it returns a `VoiceHandle` (was `void`). `pitchShift` is now in octaves (factor `2^shift`, clamped to [-1, 1]) and changes the playback rate, so a shifted sound is also shorter or longer; before, [-1, 0] and [0, 1] mapped linearly to [0.5, 1] and [1, 2] and the duration was kept. New members: `Stop`, `StopAll`, `SetVolume`, `SetPitch`, `SetPan`, `IsPlaying`, `GetBusVolume`, `SetBusVolume`. `ISoundEffect` gains `Channels` and `SampleRate`. `SoundEffect` is no longer obsolete: it is the decoded sound (float32 `Samples` at `MixRate`, `Frames`, `Channels`, `SampleRate`) and loses `WaveFormat` and `AudioData`; `SoundEffectAssetManagerExtensions` (the obsolete `Load<T>` where `T : SoundEffect`) is removed. `AudioManager`, `SoundEffectLoader` and `AudioMixer` are public. `AddAudio`/`AddNullAudio` gain overloads taking `IConfiguration` (bound from `Ion:Audio`), and `AddIon` passes its configuration. `UseNullAudio()` now adds the audio system (it added nothing). `NullAudioManager` derives from `AudioManager` and mixes on the null output as well as recording `Plays`; `SoundPlay` gains `Pan`, `Loop`, `Bus` and `Voice`. `NullSoundEffectLoader` now also decodes the samples (`NullSoundEffect.Decoded`) so headless runs mix real audio.
* **Input v2.** `InputTracker` moved from the Veldrid backend (where it was internal and linked into the null backend) to `Ion.Core.Abstractions` as the public shared implementation, and both backends' input states derive from the new `TrackedInputState`. `IInputState` gains `Text`, `Modifiers`, `Gamepads` and `Gamepad(int)`, so custom `IInputState` implementations must add them. The backends' input states take the application's `InputTracker` singleton (`AddInputTracker()`); `NullInputState` keeps its `ILoopContext` constructor and gains one taking a tracker.
* **Coroutine waits are a struct.** `Wait.For`, `Wait.Until`, `Wait.While` and `Wait.For<TEvent>` now return the `Wait` struct instead of `IWait`, and the `WaitFor`, `WaitUntil` and `WaitForEvent<T>` record structs are removed. `IWait` stays as the interface for custom waits (implement it as a class). Yielding `null` after a `Wait.Until`/`Wait.While` now resumes on the next frame instead of re-evaluating the old predicate.
* **Assets.** `UseIon()` now calls the new `UseAssets()`, which adds `AssetReloadSystem` (First, `StageOrder.AssetReload = -920`). Hot reload is on by default in Debug builds of `Ion.Extensions.Assets` (`Ion:Assets:HotReload`), where a `FileSystemWatcher` follows the assets folder; `IonTestHost` sets it to `false`.
* **Headless mode.** `AddIon(config)` registers the headless graphics and audio backends when `Ion:Headless` is `true` (`--Ion:Headless=true` on the command line) or the graphics output is `None`, and `UseIon()` adds their systems. `IsHeadless(config)` exposes the decision.
* **Screenshots.** `IonTestHost.Screenshot()` returns a `Screenshot` (width, height, RGBA8 pixels) instead of `byte[]`, and works when headless rendering is on (`WithRendering()` or `Ion:Headless:Render=true`); without it, it still throws `NotSupportedException`, now naming the switch. `AddIon` adds headless rendering on top of the null backends when `Ion:Headless:Render` is `true`, so the `Ion` package now references the Vulkan backend (`Silk.NET.Vulkan`, `Silk.NET.Core`); the NativeAOT publish of a game gains two Silk.NET.Core warnings (see the spike notes), none from Ion.
* **`GraphicsBackend.Auto`** (new, the platform default). The Veldrid backend maps it to Veldrid's platform default; the Silk.NET stack to Vulkan. `GraphicsConfig` gains `FramesInFlight`, `Validation`, `DepthBuffer`, `RetainLastFrame` and `Adapter`; `WindowConfig` gains `Resizable` and `Platform` (`WindowPlatform`: `Auto`, `Glfw`, `Sdl`).
* **Veldrid removed; `AddIon` uses the Silk.NET stack.** `Ion.Extensions.Graphics.Veldrid` (and `AddVeldridGraphics`/`UseVeldridGraphics`, `IGraphicsContext`, the obsolete `Texture2D`, `BaseTexture`, `FontSet`, `Font` types and their `Load<T>` forwarders) is deleted, which drops Veldrid, Veldrid.SPIRV, NativeLibraryLoader, `Microsoft.Extensions.DependencyModel` 2.0.3, Newtonsoft.Json and Vortice from the dependency graph. `AddIon`/`UseIon` register the Silk.NET window and input, the backend-selecting RHI graphics (`AddRhiGraphics`) and the 2D renderer through the new `AddGraphics(config, configure)`/`UseGraphics()`; headless mode is unchanged, and `Ion:Headless:Render=true` now also replaces the recording sprite batch with the real one (the null texture and font loaders are replaced by the renderer's). `GraphicsConfig.PreferredBackend` defaults to `Auto`. `GraphicsBackend` keeps `Vulkan`, `OpenGLES` and `Auto`; `Direct3D12`, `Metal` and `WebGPU` are reserved (`AddIon`/`AddGraphics` throw `NotSupportedException`, see `ThrowIfReservedBackend`); `Direct3D11` and `OpenGL` are removed.
* **`ISpriteBatch` gains `Begin(SpriteBatchOptions)`, `End()` and `SetRenderTarget(ITexture?, Color?)`.** Custom implementations must add them. The sprite batch systems still open a segment around every Render stage; explicit `Begin`/`End` nest inside it. `NullSpriteBatch` tracks nested segments (`CurrentOptions`, `CurrentRenderTarget`); its `Begin()`/`End()` keep their frame semantics at the outermost level. Depth is a sort key (`SpriteSortMode`), not a depth test: the default `Deferred` mode draws in submission order where the Veldrid batcher grouped by texture and depth-tested.
* **Samples.** `Ion.Examples.Breakout` and `Ion.Examples.Scenes` move their setup into `BreakoutApp` and `ScenesApp` (shared with their new test projects). The Breakout ECS seed no longer goes through `HashCode.Combine` (randomized per process), so a seed renders the same game in every run; the headless autopilot logs `ISpriteBatchStatistics`.

* **Metrics v2: `Ion.Extensions.Debug*` is now `Ion.Extensions.Metrics*`.** The projects, packages and namespace are renamed (`Ion.Extensions.Metrics`, `Ion.Extensions.Metrics.Abstractions`); `AddIon`/`UseIon` call the new `AddMetrics(config)`/`UseMetrics()`. `AddDebugUtils`/`UseDebugUtils` (in `Ion.Extensions.Debug`), `DebugConfig`, `ITraceTimer`, `ITraceTimer<T>`, `ITraceTimerInstance`, `ITraceManager`, `NullTimerInstance` and `TraceTiming` are `[Obsolete]` adapters over the frame profiler for one release: `AddDebugUtils` forwards to `AddMetrics` and maps `Ion:Debug:TraceEnabled`/`TraceOutput` onto `Ion:Metrics:Profiling`/`TraceOutput`; `ITraceTimer<T>` (still registered by the core) records `{T}::{name}` spans into the profiler while it is recording (reusing stopped instances, so a timer started every frame stops allocating after warm-up) and returns a shared no-op instance otherwise; the Veldrid backend still times itself through it. `TraceTimerSystem`, `TraceManager` and the core's `NullTraceTimer<T>` are removed (the loop records a span per stage itself). Tracing works in Release builds: it is off until `Ion:Metrics:Profiling`, `IMetrics.IsProfiling` or a capture turns it on, and the trace is bounded by the ring (the old `ConcurrentBag` grew without limit).
* **`GameLoop` constructor.** `GameLoop(IOptionsMonitor<GameConfig>, EventBus, IClock, GameLoopContext? = null, FrameProfiler? = null, IEnumerable<IFrameStatsSource>? = null)` replaces the overload taking `ITraceTimer<GameLoop>`. `EventSystem` takes a `FrameProfiler`, and `SceneSystem` no longer takes a trace timer (the schedule times its steps).
* **Generated schedules call the profiler.** The generator brackets every step and scope with `FrameProfiler.Begin`/`End` behind the `Ion.Metrics.Profiling` feature switch, so generated code needs this version of `Ion.Core.Abstractions`; `<IonMetricsProfiling>false</IonMetricsProfiling>` emits the old shape.

* **RHI: cube maps and sampled depth.** `ITexture` gains `Dimension` (`TextureDimension.D2` or `Cube`), so custom `ITexture` implementations must add it; `TextureDescriptor` gains a trailing `Dimension` and `TextureRegion` a trailing `ArrayLayer` (both optional, existing calls compile unchanged). Depth textures created with `TextureBinding` can be sampled (comparison samplers for shadow maps). The GLES backend's empty fragment stage for depth-only pipelines now takes the vertex stage's GLSL ES version (it declared 3.00 and failed to link with 3.10 vertex stages).
* **Render stage order.** New `StageOrder.Rendering3D` (-860): the 3D renderer's scope opens between the graphics frame scope and the sprite batch scope and closes after the sprite batch's, then draws the sprite batch's frame as its last pass (`SpriteBatch.DeferSubmission`, set by the 3D renderer only). Games without `AddRendering3D` are unaffected.

### ✨ Features

* **Silk.NET graphics stack, first wave (Stage 4).** Findings of the spike (Silk.NET 2.23 windowing driven by Ion's loop, Vulkan under lavapipe, NativeAOT) in `docs/plans/spikes/2026-silknet-spike.md`.
  * **RHI** (`Ion.Extensions.Graphics.Rhi` in `Ion.Extensions.Graphics.Abstractions`): WebGPU-shaped `IGraphicsDevice`, `IQueue`, `IBuffer`, `ITexture`, `ITextureView`, `ISampler`, `IShaderModule`, `IBindGroupLayout`, `IBindGroup`, `IPipelineLayout`, `IRenderPipeline`, `ICommandEncoder`, `IRenderPassEncoder`, `ICommandBuffer` and `ISurface`, descriptor structs (vertex layouts, primitive, depth, blend targets with `AlphaBlend`/`PremultipliedAlpha`/`Additive` presets, samplers) and enums (formats, usages, blend, compare, cull). Frames in flight are explicit (`BeginFrame`/`EndFrame`), queue writes are ordered with submissions as in WebGPU, destruction is deferred until the GPU is done, and the GLES 3.1 mapping constraints are documented on the types. Engine-level: `IGraphicsFrame` (the frame's targets and clear-on-first-use attachments), `IScreenshotSource`, `Screenshot`/`Rgba8`, `IWindowSurface` with native handles, and `EmbeddedShaders`.
  * **`Ion.Extensions.Windowing.SilkNet`** (new): `SilkWindow` created at Init (`StageOrder.Window`) and pumped with `DoEvents()` in `First`, GLFW or SDL registered explicitly from `Ion:Window:Platform` (no reflection discovery), resize/focus/close on `IEvents`, fullscreen/borderless/resizable/vsync from configuration; `SilkInputState` feeds keyboard (derived repeats and modifiers), mouse, wheel, text and gamepads (buttons, sticks, triggers, connections) into the shared `InputTracker`, queued during `DoEvents` and applied at `StageOrder.Input`.
  * **`Ion.Extensions.Graphics.Vulkan`** (new): the RHI on `Silk.NET.Vulkan`: validation layer and debug messenger when requested and installed, device selection by type or `Ion:Graphics:Adapter`, one graphics and present queue, swapchain with recreation on resize or out-of-date, 2 or 3 frames in flight with per-frame command pools, fences, staging ring and deferred destruction, render pass cache, descriptor pools, SPIR-V shader modules, MoltenVK portability extensions. `GraphicsFrameDriver` (RHI-only, for the GLES backend too) drives frames, clears, presents and captures; `AddVulkanGraphics`/`UseVulkanGraphics` register it. Runs clean under synchronization validation.
  * **`Ion.Extensions.Graphics.Headless`** (new): the Vulkan backend without a surface, into an offscreen color and depth target sized from `Ion:Window`, with RGBA8 capture and PNG screenshots.
  * **Build-time shaders** (`Ion.Shaders`, new): `Ion.Shaders.targets` compiles `IonShader` items (GLSL 4.5) to SPIR-V with Shaderc and to GLSL ES 3.10 with SPIRV-Cross (combined image samplers, GL depth range), embeds both, and fails the build on errors with file and line.
  * **NativeAOT**: ILLink substitutions stub the Silk.NET code Ion never runs (reflection platform discovery, deps.json native probing), imported in the repository and shipped as `buildTransitive`. The quad sample publishes with no Ion warnings; CI publishes it in the AOT lane.
  * **Golden images** (`Ion.Testing`): `IonTestHost.WithRendering()`, `Screenshot()`, `SaveScreenshot(path)`, and `GoldenImage` (`Compare`, `AssertMatches` with tolerance and mismatch ratio, missing goldens written and failed, `.actual.png`/`.diff.png` on mismatch, `ION_UPDATE_GOLDEN=1`, `Load`, `Save`).
  * **`Ion.Examples.Quad`** (new): a checkerboard quad through the RHI on a Silk.NET window, or offscreen with `--Ion:Headless=true`, with `--Quad:Frames` and `--Quad:Screenshot`.
  * **`Ion.Extensions.Graphics.Vulkan.Tests`** (new, 55 tests): headless quad with pixel checks and golden PNGs (device level and through `IonTestHost`), write ordering, texture region uploads, frames in flight, clear color, capture errors, the shader pipeline, Silk.NET input mapping and queueing, and windowed E2E tests on GLFW and SDL with swapchain recreation (under `xvfb-run`). Every Vulkan test fails on validation errors; tests skip without a Vulkan driver or a display. CI installs lavapipe, the validation layers and Xvfb.
* **OpenGL ES backend and backend selection (Stage 4, second wave).** The R36S handheld's backend, and the fallback wherever Vulkan is missing.
  * **`Ion.Extensions.Graphics.GLES`** (new): the RHI on `Silk.NET.OpenGLES`, OpenGL ES 3.1 with ES 3.2 native base vertex and ES 3.0 fallbacks (`GlesFeatureLevel`; `Ion:Graphics:Gles:MaxFeatureLevel` forces one): command buffers recorded and replayed at submit so queue writes keep WebGPU ordering, whole-buffer writes orphan their storage, `glTexStorage2D` textures and sampler objects, pipelines as program + vertex array + state (separate attribute formats on ES 3.1, attribute pointers on ES 3.0), bind groups on the flattened slots, render passes as cached framebuffer objects with `glClearBuffer` and `glInvalidateFramebuffer`, readback through a pixel pack buffer (CPU conversion for R8, RG8, BGRA and float formats), frames in flight on fence syncs with deferred deletion, `glGetError` checks under `Ion:Graphics:Validation`. The window surface renders into an offscreen target per frame slot and is blitted to the default framebuffer with a vertical flip at present. Contexts: the Silk.NET window's GL context (`SilkWindow` now creates a GL ES 3.1 context, falling back to 3.0, when the backend is OpenGL ES) or a headless EGL context (`EglContext`: Mesa's surfaceless platform, else a 1x1 pbuffer; EGL loaded through `NativeLibrary`, no bindings package). `AddGlesGraphics`/`UseGlesGraphics`.
  * **Shader build** (`Ion.Shaders`): the GLSL ES translation flattens `(set, binding)` to `set * 8 + binding` (`GlesBindings`, one source shared with the abstractions), writes `layout(binding = N)` and a flattening table (comment lines naming each uniform block and combined sampler with its slot and sampler binding), negates clip-space y and names varyings by location. One texture sampled with two samplers is a build error.
  * **Backend selection**: `GraphicsBackendSelector` resolves `GraphicsConfig.PreferredBackend`: `Vulkan` or `OpenGLES` are forced, `Auto` takes the first available in platform order (Vulkan then OpenGL ES on desktop, OpenGL ES first on linux-arm64). `RhiGraphics` (in `Ion.Extensions.Graphics.Headless`, `AddRhiGraphics`/`UseRhiGraphics`) picks the backend at Init, windowed or offscreen; headless rendering (`Ion:Headless:Render`) uses it, so it runs without Vulkan. `WindowConfig.Fullscreen` is shorthand for `WindowState = FullScreen`.
  * **Shared frame driver**: `GraphicsFrameDriver` moves from the Vulkan package to `Ion.Extensions.Graphics.Abstractions` (same namespace) with `IRhiGraphics`, and saves PNGs with a BCL-only `PngWriter` instead of ImageSharp.

* **Metrics v2: frame profiler** (`Ion.Core.Abstractions`). `FrameProfiler` keeps a preallocated ring of `FrameProfile`s (`Ion:Metrics:HistoryFrames`, default 300, each with room for `SpansPerFrame` spans, default 512) of `SpanRecord(SpanId, ThreadId, Start, End)`; span names are interned once with `MetricsIds.Register("Physics.Step")` (`SpanId`, engine ids in `SpanIds`) and resolved only at export. `profiler.Scope(id)` returns a `MetricsScope` ref struct for `using`; `Begin(id)`/`End(id, start)` are the raw pair; `Record` takes explicit timestamps. `FrameProfiler.IsProfilingEnabled` is the `Ion.Metrics.Profiling` feature switch (`[FeatureSwitchDefinition]`, `RuntimeHostConfigurationOption` set from the `IonMetricsProfiling` MSBuild property by the Ion props, default true) and `IsActive` the runtime toggle. The generated schedule brackets every step and scope, the runtime schedule does the same through `IStepProfiler`, and the loop records a span per stage and for idle time, and a profile for Init and Destroy. `ISpanSink` receives spans live, `IFrameListener` every completed frame. Scope enter and exit: 0.77 ns and 0 B disabled, 76 ns and 0 B enabled on the benchmark VM (two `Stopwatch` reads at 40 ns each); a generated stage with profiling compiled in but off costs one check (8 systems: 63 ns per frame); see `MetricsBenchmarks` and `docs/plans/benchmarks/2026-09-25-stage3-metrics`.
* **Frame stats.** `FrameStats` is written once per frame when metrics are installed: frame, delta, wall-clock frame and idle time, fixed steps, draw calls, sprites and triangles (from `ISpriteBatchStatistics`, new in `Ion.Extensions.Graphics.Abstractions` and implemented by the null sprite batch and the 2D renderer's `SpriteBatch`), entities (`IFrameStatsSource` hook for an ECS; the Breakout ECS sample counts its Arch world), events emitted, GC collections per generation and bytes allocated by the loop thread during the frame, and span counts. `IFrameStatsSource` adds counters; `FrameProfiler.LastFrame`, `IMetrics.LastFrame` and `IonTestHost.LastFrame` read them.

* **Events v2: typed channels.** `IEvents` (`Emit<T>(in T)`, `Reader<T>()`, and the `Emit<T>()` extension for events without data) replaces the boxed bus. `EventBus` keeps one `EventChannel<T>` per event type: an array holding the fixed-step backlog, the previous frame and the current frame, compacted only when the dropped prefix is half of it and never shrunk, found through a per-type slot (the runtime fallback keeps them in a dictionary keyed by type). `EventReader<T>` is a struct holding the channel and a cursor, with `TryRead`, `Read` (a `ReadOnlySpan<T>` of every unread event), `TryReadLatest`, `Any`, `Count` and `Skip`; `EventReaderSet` keeps one reader per type for code that reads types chosen by its caller. Same semantics as before: visible in the frame of the emit and the next, each reader sees each event once, and readers in `FixedUpdate` see the backlog. Emit and read do not allocate. `EventId<T>` (with `EventIds`) gives each event type an integer id, compile-time when the generator saw it; `EventSystem` logs channel growth by id. `IonApplicationBuilder.UseEventBus(factory)` installs another bus. 100 events of 4 types read by 8 readers: 650 ns and 0 B per frame, against 1.5 ms and 3,600 B with the old `On<T>` listeners (`docs/plans/benchmarks/2026-09-25-stage3-events`).
* **Generated event bus.** The source generator sees every `Emit`/`Reader` call (and every method marked with the new `[EmitsEvent]`/`[ReadsEvent]`, such as `EmitChangeScene`, `Wait.For<T>()` and `IonTestHost.Collect<T>()`), writes an `[assembly: EventUsage(type, usage)]` summary for each assembly, and for an application intercepts `IonApplication.CreateBuilder` to install a file-local `GeneratedEventBus`: one typed channel field per event type used by the game or the Ion assemblies it references, compile-time ids registered with `EventId<T>`, initial capacities from usage (256 when emitted in a loop in `FixedUpdate`/`Update`, 64 when emitted there, 16 otherwise, 4 when only read), and the game's `Emit`/`Reader` calls intercepted to touch the field directly. Types it cannot see fall back to runtime channels on the same bus.
* **Event diagnostics.** `ION101` emitted but never read, `ION102` read but never emitted (warnings, for applications), `ION103` reader created in a per-frame stage method (warning), `ION104` payload not unmanaged (error, names the field), `ION105` read in an earlier stage than it is only emitted in (info: one frame of latency), `ION106` reader in a `readonly` field or a property (warning: reads advance a copy). They found two real bugs in the Breakout ECS sample, which listened for wall and paddle hits nobody emitted (the bonk sound never played) and emitted a ball-lost event nobody read; the sample now emits both hits and counts lost balls.
* **Compile-time schedule (`Ion.Generators`, new).** A Roslyn source generator, shipped as an analyzer of the `Ion` and `Ion.Core` packages (whose build props add `Ion.Generated` to `InterceptorsNamespaces`), intercepts `UseSystem`, function steps (`app.Update(...)`), legacy middleware (`app.UseUpdate(...)`), `UseScene` and `Build()`/`Run()`/`RunFrames()` with C# interceptors, and emits: a reflection-free description of every system (steps, scopes, constraints, diagnostics and direct-call binders, `GeneratedSystem`); for each application and scene a `GeneratedSchedule` with one method per stage that calls every step directly in plan order, with a `try/finally` per scope and the systems resolved once in its constructor; and a `ScheduleRegistrations` summary of every method that takes a builder, so an application sees what library helpers such as `UseIon()` register. The generated schedule runs only when the registrations made at run time and their plan match what the generator saw (conditional registrations are guarded); otherwise the runtime binds the pre-bound registrations, and anything the generator cannot see (a `Type` only known at run time, a plugin) stays on the reflection path. 32 systems in one stage: 15.7 ns against 13.3 ns for hand-written direct calls (runtime-bound: 67 ns); a full headless frame with 8 systems: 46 ns against 125 ns; no allocation per frame. The Breakout ECS sample publishes with NativeAOT with no Ion warnings and runs its generated schedule.
* **Schedule diagnostics at compile time.** `ION001` to `ION013` are reported by the generator with the runtime's ids, severities and messages (`ION008`, `ION009` and `ION006` for types declared in the project that no registration call mentions, `ION002` for cycles among unconditional registrations, `ION012` when the generator sees every registration), plus `ION014` when interceptors are not enabled.
* **Runtime support for generated code** (`Ion.Core.Abstractions`): `ScheduleModel.AddSystem(GeneratedSystem, site)`, `AddFunction`/`AddMiddleware` overloads with precomputed names, constraints and call sites, `ScheduleEntry.Site`, `ScheduleModel.UseGenerated(...)`, `Schedule.IsGenerated`/`Generated`, `GeneratedSchedule`, `GeneratedScheduleFactory` and `GeneratedScheduleContext`, and `StepAdapters`. * **Function steps.** `app.Init(...)`, `app.First(...)`, ..., `app.Destroy(...)` (and the same on `ISceneBuilder`) register a delegate as a step: `Action<GameTime>`, or `Action<GameTime, T1..T4>` with the services resolved once. Optional `order` and `name`.

* **Unboxed coroutine waits.** `Wait` is a readonly struct union (`Kind`, `Seconds`, and one reference for the predicate, a cached per-type event check, a nested routine or a custom `IWait`) copied into the coroutine's handle, and `IEnumerator<Wait>` coroutines are read without boxing. `Wait.For(IEnumerator)` nests routines, `Wait.For(IWait)` wraps custom waits, `Wait.None` resumes next frame, and floats and `TimeSpan`s convert implicitly. `CoroutineBenchmarks.Update100Coroutines`: 1.90 us and 2.34 KB per frame before, 765 ns and 0 B after (the non-generic `IEnumerator` form, kept as `Update100LegacyCoroutines`, is 1.83 us and 3.2 KB because the routine boxes each yielded struct).

## [0.2.5](https://www.github.com/jimbuck/Ion/releases/tag/v0.2.5) (2025-1-2)

* **Input v2** (`Ion.Core.Abstractions`): fixed-size input state in `ulong` bitsets indexed by `Key` (held, pressed and released, for both the per-frame and fixed-step views), 32-bit masks for mouse and gamepad buttons, mouse position and delta, wheel, per-frame text input (`IInputState.Text`, a `ReadOnlySpan<char>` fed from the Veldrid snapshot's character events), held `Modifiers`, and eight gamepad slots (`IGamepadState`: `Down`/`Up`/`Pressed`/`Released(GamepadButton)`, `Axis(GamepadAxis)`, `LeftStick`, `RightStick`) with a radial dead zone from `Ion:Input:GamepadDeadZone` (`InputConfig`, default 0.15). No allocation per frame (checked by a test). Modifier and focus-loss semantics are documented on `InputTracker`. The Veldrid backend exposes no gamepads (Veldrid's SDL2 snapshot has no controller events); the Silk.NET backend in Stage 4 will feed them. `NullInputState` scripts text (`Type`), key repeats (`Repeat`) and gamepads (`ConnectGamepad`, `DisconnectGamepad`, `Press`/`Release`/`Tap(pad, button)`, `SetAxis`, `SetLeftStick`, `SetRightStick`).
* **Recorded input.** `AddInputRecording(path)` records every frame's input events with `InputRecorder` into a compact binary stream (`InputRecordingFormat`: frame blocks of 7-bit encoded frame numbers and events, with an end marker); `AddInputPlayback(path)` replays it with `InputPlayer` at the recorded frame numbers into any `IInputEventSink`, replacing device input until the recording ends. `IInputEventSink`, `IInputRecorder`, `IInputPlayback`, `IInputTrackerHook` and the `InputEvent` value type are public. A test records 100 frames of random input in `IonTestHost` and replays it into another host with identical `Pressed`/`Down` sequences, per frame and per fixed step.
* **Unboxed coroutine waits.** `Wait` is a readonly struct union (`Kind`, `Seconds`, and one reference for the predicate, a cached per-type event check, a nested routine or a custom `IWait`) copied into the coroutine's handle, and `IEnumerator<Wait>` coroutines are read without boxing. `Wait.For(IEnumerator)` nests routines, `Wait.For(IWait)` wraps custom waits, `Wait.None` resumes next frame, and floats and `TimeSpan`s convert implicitly. `CoroutineBenchmarks.Update100Coroutines`: 1.90 us and 2.34 KB per frame before, 765 ns and 0 B after (the non-generic `IEnumerator` form, kept as `Update100LegacyCoroutines`, is 1.83 us and 3.2 KB because the routine boxes each yielded struct).
* **Asset hot reload.** `IAssetWatcher` (`AssetWatcher`: a `FileSystemWatcher` over the assets root with a 100 ms settle time, or manual `Enqueue`), `AssetReloadSystem` (reloads every cached asset of a changed path in the global and scene caches, emits `AssetReloadedEvent(AssetId, PreviousAssetId)`), and `IReloadableAssetLoader` for in-place updates, implemented by the null texture and font loaders and by the Veldrid texture loader (pixels re-uploaded into the same device texture when the size is unchanged). Other assets are loaded again and swapped into the cache.
