The R36S is a small Linux handheld: a Rockchip RK3326 (4x Cortex-A35), a Mali-G31 MP2 GPU, a 640 x 480 panel and 1 GB of
RAM, running ArkOS (an Ubuntu-based linux-arm64 distribution with Mesa's Panfrost driver). Ion has a publishing preset
for it that produces a NativeAOT binary and a ready-to-copy SD card folder.

## The handheld profile

Panfrost's OpenGL ES 3.1 is the stable graphics API on the device (PanVK, the Vulkan driver, is experimental), and
ArkOS has no X server, so an Ion game there uses:

| Layer | Choice |
|---|---|
| Graphics | `Ion.Extensions.Graphics.GLES` (OpenGL ES 3.1, with ES 3.0 fallbacks) |
| Windowing and input | `Ion.Extensions.Windowing.SilkNet` on the SDL platform (ArkOS ships SDL2 with KMSDRM) |
| Build | NativeAOT, `linux-arm64` |
| Window | fullscreen at the panel's 640 x 480 |
| Controls | the built-in gamepad, through SDL (`input.Gamepad(0)`) |

`GraphicsBackend.Auto` already prefers OpenGL ES on linux-arm64, so a game that uses the backend-selecting graphics
picks GLES there and Vulkan on desktop from the same build. The `r36s` preset makes the choice explicit in the
handheld's configuration file.

## Publish in three commands

```bash
python3 build/arm64-sysroot.py ~/sysroot-bionic-arm64        # once: Ubuntu 18.04's arm64 glibc 2.27 runtime
dotnet publish Ion.Examples/Ion.Examples.Breakout.ECS -p:IonTarget=r36s -p:IonArm64SysRoot=$HOME/sysroot-bionic-arm64
ion publish Ion.Examples/Ion.Examples.Breakout.ECS --target r36s --sysroot ~/sysroot-bionic-arm64   # the same, with the ion tool
```

Host packages (Ubuntu or Debian): `clang lld llvm zlib1g-dev python3 dpkg` for the build (`llvm` provides the
`llvm-objcopy` that strips arm64 symbols; GNU `objcopy` cannot read arm64 binaries), and `qemu-user-static` if you want
to run the result on the build machine.

The preset is a NativeAOT `linux-arm64` publish (see [Publishing](/Ion/platforms/publishing/)) with EventSource off,
invariant globalization and stripped symbols, plus two handheld extras:

1. `appsettings.r36s.json` in the publish folder (unless your game ships its own).
2. The ArkOS SD card layout in `<publish dir>-arkos/`.

## The handheld configuration

The preset writes this file from `build/arkos/appsettings.r36s.json`:

```json title="appsettings.r36s.json"
{
  "Ion": {
    "Window": { "Platform": "Sdl", "Fullscreen": true, "Width": 640, "Height": 480, "ShowCursor": false },
    "Graphics": { "PreferredBackend": "OpenGLES", "VSync": true, "FramesInFlight": 2 }
  }
}
```

The launcher sets `DOTNET_ENVIRONMENT=r36s`, so the host's `appsettings.{Environment}.json` convention loads it over
`appsettings.json`. The same settings work on the command line, which is handy for trying the profile on a desktop:

```bash
dotnet run --project MyGame -- --Ion:Window:Platform=Sdl --Ion:Window:Fullscreen=true \
  --Ion:Window:Width=640 --Ion:Window:Height=480 --Ion:Graphics:PreferredBackend=OpenGLES
```

`Ion:Window:Fullscreen = true` is shorthand for `Ion:Window:WindowState = FullScreen`.

:::tip[Check the ES 3.0 and 3.1 paths on a desktop]
Desktop Mesa reports OpenGL ES 3.2. Add `--Ion:Graphics:Gles:MaxFeatureLevel=Es31` to run at the Mali-G31's level, or
`Es30` to see what an ES 3.0-only device would run.
:::

The defaults the preset writes come from MSBuild properties you can override in the game's project:

| Property | r36s value |
|---|---|
| `IonDefaultGraphicsBackend` | `OpenGLES` |
| `IonDefaultWindowPlatform` | `Sdl` |
| `IonDefaultFullscreen` | `true` |
| `IonDefaultWidth`, `IonDefaultHeight` | `640`, `480` |

## The ArkOS SD card layout

```
<publish dir>-arkos/
  README.md                            installation notes
  ports/<name>.sh                      the launcher shown in the Ports menu
  ports/<name>/<executable>            the NativeAOT binary
  ports/<name>/libSDL2-2.0.so          (replaced at launch by the system SDL2)
  ports/<name>/libopenal.so
  ports/<name>/appsettings.json
  ports/<name>/appsettings.r36s.json
  ports/<name>/Assets/...
```

| Property | Default | Meaning |
|---|---|---|
| `IonArkOSDir` | `<publish dir>-arkos` | Where the layout is written. |
| `IonArkOSName` | the assembly name | The game's folder and script name. |
| `IonArkOSTitle` | `IonArkOSName` | The title in the README and the script. |
| `IonArkOSLayout` | `true` for `r36s` | Set `false` to skip the layout. |

The debug symbols (`.dbg`) and the unused GLFW library (`libglfw.so.3`) stay out. You can rebuild the layout from an
existing publish folder without publishing again:

```bash
dotnet msbuild MyGame -t:IonArkOSLayout -p:IonTarget=r36s -p:PublishDir=path/to/publish/
```

If the publish folder has no executable, this stops with `IONPUB004`.

### Installing on the card

Copy `ports/` onto the card's ports folder (`/roms/ports`, or `/roms2/ports` on a two-card setup) and restart
EmulationStation. The game appears in the **Ports** menu.

### What the launcher does

```bash title="ports/<name>.sh (abridged)"
GAMEDIR="$(cd "$(dirname "$0")/@NAME@" && pwd)"
cd "$GAMEDIR" || exit 1

# Use the system SDL2 (KMSDRM and the device's controls) instead of the bundled generic one.
for sdl in /usr/lib/aarch64-linux-gnu/libSDL2-2.0.so.0 /usr/lib/libSDL2-2.0.so.0; do
  if [ -e "$sdl" ]; then
    ln -sf "$sdl" libSDL2-2.0.so 2>/dev/null || cp -f "$sdl" libSDL2-2.0.so
    break
  fi
done

export DOTNET_ENVIRONMENT=r36s
"./@EXE@" "$@" > "$GAMEDIR/log.txt" 2>&1
```

- Silk.NET opens `libSDL2-2.0.so` next to the executable first. The bundled one is a generic build without the
  device's video drivers, so the launcher replaces it with the system SDL2. exFAT cards have no symbolic links, so it
  copies when linking fails.
- The game's output goes to `ports/<name>/log.txt`: read it on a PC if the game does not start.
- EGL and GLES come from the device's Mesa.

## Cross-compiling from Linux x64

NativeAOT cross-compiles to arm64 with clang and lld; the x64 ILCompiler compiles for arm64, so no arm64 .NET SDK is
needed. The restore downloads the arm64 runtime packs (`Microsoft.NETCore.App.Runtime.linux-arm64` and
`Microsoft.NETCore.App.Runtime.NativeAOT.linux-arm64`). On a Linux x64 machine the preset sets `LinkerFlavor=lld` and
passes `IonArm64SysRoot` (a property or an environment variable) as `SysRoot`.

The one extra input is a sysroot whose glibc is **not newer than the device's**. ArkOS is based on Ubuntu 19.10
(glibc 2.30), and .NET 10 needs glibc 2.27 or later, so Ubuntu 18.04's arm64 packages are the right base.
`build/arm64-sysroot.py <dir>` downloads Ubuntu 18.04's arm64 `libc6`, `libc6-dev`, `linux-libc-dev`, `libgcc-7-dev`,
`libgcc1`, `libstdc++-7-dev`, `libstdc++6`, `zlib1g` and `zlib1g-dev` from ports.ubuntu.com, extracts them with
`dpkg-deb -x` and makes their absolute symbolic links relative.

:::caution[IONPUB003: no sysroot]
Without `IonArm64SysRoot`, the Ubuntu cross packages (`libc6-dev-arm64-cross`, `libgcc-13-dev-arm64-cross`) also link,
but the binary then needs the build machine's glibc (2.34 or later) and does not start on ArkOS. The preset warns with
`IONPUB003`.
:::

The same flags without the preset, for reference:

```bash
dotnet publish MyGame -c Release -r linux-arm64 -p:PublishAot=true -p:SysRoot=$HOME/sysroot-bionic-arm64 -p:LinkerFlavor=lld
```

## Running the arm64 build under QEMU

```bash
cd <publish dir>
qemu-aarch64-static -L ~/sysroot-bionic-arm64 ./Ion.Examples.Breakout.ECS --Ion:Headless=true --Ion:Run:Frames=1
```

`-L` points the emulator's dynamic loader at the sysroot. Rendering under QEMU (EGL, llvmpipe) also needs Ubuntu 18.04's
arm64 Mesa in the root.

## Designing for the handheld

- **Gamepad first.** The device has no mouse or touch screen. Read `input.Gamepad(0)` (the SDL game controller layout:
  `GamepadButton.A`, `B`, the D-pad, sticks). The [UI module](/Ion/interaction/ui/overview/) focuses the first widget
  automatically, so the D-pad alone drives every screen; the [Menu sample](/Ion/examples/menu/) is tested that way.
- **640 x 480.** Lay out from `IWindow.Width` and `Height`. A fixed desktop layout such as Breakout's 2030 x 984 play
  field needs a scaled view (a virtual resolution in the 2D renderer), which Ion does not provide yet.
- **One slow core at a time.** Keep work off the frame where you can, and measure on the device.

```csharp
public sealed class HandheldControls(IInputState input)
{
	[Update]
	public void Read(GameTime dt)
	{
		var pad = input.Gamepad(0);
		if (!pad.IsConnected) return;
		var move = pad.LeftStick;                      // dead zone applied (Ion:Input:GamepadDeadZone)
		if (pad.Down(GamepadButton.DPadLeft)) move.X -= 1;
		if (pad.Down(GamepadButton.DPadRight)) move.X += 1;
		if (pad.Pressed(GamepadButton.A)) { /* jump */ }
	}
}
```

## What has been verified, and what has not

**Verified (September 2026):**

- Breakout ECS published with `-p:IonTarget=r36s` against the glibc 2.27 sysroot (11.6 MB executable, `GLIBC_2.27` at
  most) runs headless under `qemu-aarch64-static` on an x64 host: 0.6 s from process start to exit after one frame,
  median of 10. That is emulated, so it is an upper bound unrelated to the Cortex-A35's speed. CI's AOT lane repeats
  this on every pull request and uploads the ArkOS layout.
- The ArkOS layout (launcher, README, handheld configuration) is produced by the publish and checked by
  `Ion.Tools.Tests.PublishProfileTests`.
- The Quad sample cross-published for linux-arm64 runs under `qemu-aarch64` with Ubuntu 18.04's arm64 Mesa 20.0.8
  (llvmpipe, OpenGL ES 3.1, the same level as Panfrost on the Mali-G31), picks OpenGL ES through `Auto`, and writes a
  frame identical to the x64 Vulkan and GLES goldens, at the ES 3.1 and ES 3.0 feature levels.

**Not verified:** real R36S hardware, the Panfrost driver, SDL's KMSDRM video driver, fullscreen at 640 x 480, gamepad
input through SDL on the device, the launcher on ArkOS, and frame times and startup on the Cortex-A35 (the acceptance
target is under one second).

## Other Linux arm64 handhelds

Nothing in the preset is specific to the R36S except the defaults and the ArkOS layout. For another RK3326 or similar
device, publish with `-p:IonTarget=linux-arm64` (the plain arm64 preset, which keeps `EventSourceSupport` on and writes
no layout), ship your own `appsettings.<device>.json`, and set `DOTNET_ENVIRONMENT` in your launcher. Or publish with
`r36s` and override `IonArkOSName`, `IonDefaultWidth` and `IonDefaultHeight`.
