# Writing the Ion docs site

The site is Astro + Starlight in `website/`, deployed to GitHub Pages at https://jimbuck.github.io/Ion/.
Search is Pagefind (built into Starlight; the index is generated by `npm run build`).

## Layout

Pages live in `src/content/docs/<section>/`. The sidebar is generated per directory (see `astro.config.mjs`):

| Directory | Sidebar section |
|---|---|
| `getting-started/` | Getting started |
| `concepts/` | Core concepts |
| `rendering/` | Rendering |
| `ecs/` | ECS and scenes |
| `interaction/` | Audio, input and UI |
| `physics/` | Physics |
| `networking/` | Web and networking |
| `tooling/` | Tooling and testing |
| `platforms/` | Platforms and publishing |
| `examples/` | Examples |
| `reference/` | Reference |

Subdirectories become nested sidebar groups.

## Page rules

- Prefer `.md`. Use `.mdx` only when you need components (`Tabs`, `TabItem`, `Steps`, `Card`, `LinkCard`,
  `FileTree`, `Badge` from `@astrojs/starlight/components`). In `.mdx`, `{`, `}` and `<` in prose must be escaped or
  put in code spans.
- Frontmatter: `title`, `description` (one sentence, used by search and social cards), and `sidebar: { order: N }`.
- Asides: `:::note`, `:::tip`, `:::caution`, `:::danger` (with optional `[Title]`).
- Code fences: `csharp`, `json`, `xml`, `bash`, `powershell`. Use `title="Program.cs"` for file names and
  `// [!code highlight]`-free plain code; Expressive Code supports `{2-4}` line markers after the language.
- Internal links are absolute and include the base: `/Ion/concepts/stages/`. Always end with `/`. Broken links fail
  the build (starlight-links-validator). Link to `https://github.com/jimbuck/Ion/blob/main/...` for source files.
- Every API name, option, config key, diagnostic id and default value must be verified in the source code. Never invent
  API. If something is planned but not built, say so plainly.
- Examples must compile against the current API: prefer snippets adapted from `Ion.Examples/`, `templates/` and tests.
- No em-dashes anywhere (the U+2014 character). Use commas, colons, parentheses or separate sentences.
- Voice: second person, present tense, concise. Lead with what the reader wants to do, then explain.

## Commands

```bash
cd website
npm ci
npm run dev      # http://localhost:4321/Ion/
npm run build    # static site + Pagefind index in dist/
```
