# Ion engine v0.3: session writeup

One session took the Ion engine from a review of a 16k-line C# codebase to a 106k-line engine with ECS, a Silk.NET rendering layer, audio, UI, physics, networking, an agentic toolchain and native builds, delivered as [jimbuck/Ion#52](https://github.com/jimbuck/Ion/pull/52) with CI green on Ubuntu, Windows and macOS.

The numbers below come from the git history of the feature branch, the session transcript and the CI logs. Estimates are marked as such.

| Agent working time | about 1,060 agent-minutes (17.7 hours) inside 16.4 wall-clock hours |
| Agent tool calls | 3,848 |
| Coordinator turns | 843 |

The parallelism was the efficiency lever: waves of up to four agents worked in isolated git worktrees on disjoint file sets, and each wave was squash-merged, built, tested under Xvfb and pushed before the next one started. Net output was about 5,500 lines of C# per wall-clock hour, roughly a third of it tests.

Time lost to overhead: two usage-limit pauses, one container restart that killed three running agents (their worktrees survived and they resumed from disk), and one context compaction. The restart cost roughly 45 minutes of agent time; the rate limits cost nothing but wall-clock.

Implementation agents (Claude Opus 5.5, $4 input, $20 output, $0.20 cache read per million tokens): the harness reports one token figure per agent, 11.5M in total, without an input, output and cache split. Valuing it all as uncached input gives $46; adding a plausible 10 percent output share gives about $64; a coordinator-like cache profile would be far less. Adding the unreported first runs of the three agents lost to the restart (roughly 1.5M tokens more), a fair estimate for agents is $50 to $90.

**Estimated total: $280 to $320 at list prices**, for about 90,000 net new lines of engine code, 29,500 lines of tests, a CI matrix on three operating systems, and 4,000 lines of design documents. That is about $3 per thousand lines including tests, or under $1 per test.

The coordinator was the larger cost even though it wrote almost no code: 843 turns of merging, verifying, unblocking agents and driving CI, each re-reading a large cached context. Cache reads were 98 percent of its input, which is what kept it at $227 rather than several thousand dollars.

## Major issues

- **Container restart mid-wave.** Three running agents were killed. Their worktrees survived on disk with partial commits, so replacements resumed from that state; the cost was about 45 agent-minutes and a rebase. Agents were told afterwards to commit early and often.
- **Usage limits.** Two session-limit pauses stopped the coordinator and one agent (the networking agent, mid-way through its sample tests). Both resumed with context intact. No work was lost.
- **Silk.NET native loading on Ubuntu.** The most instructive bug: Silk.NET maps distribution-specific runtime identifiers to the portable `linux-x64` NuGet folder only for a hard-coded list of distributions, and Ubuntu is not on it. On a machine without the system GLFW and SDL packages, every window platform reported as "not applicable". A system SDL package installed earlier had masked this locally, so it surfaced only on the CI runner, and the first fix (installing X11 libraries) treated a symptom. Diagnosed by decompiling Silk.NET's resolver; fixed with an app-local resolver in the windowing module and verified with the masking package removed. This would have hit every Ubuntu user running a framework-dependent game.
- **Windows-only test failures.** Five distinct root causes surfaced the first time the suite ran on Windows: CRLF checkouts changing the hash inside generator goldens, an unescaped path in JSON, thread-pool starvation between tests, windowed OpenGL tests with no driver, and a case-insensitive file system. All fixed at the root rather than skipped.
- **macOS accept-thread crash.** `TcpListener` throws a different exception after `Stop()` on macOS; an unhandled exception on the accept thread took the whole test host down.
- **Tooling blocked by the proxy.** Microsoft download hosts, the Android SDK and Apple toolchains were unreachable, so .NET came from apt, the mobile heads and cross-OS publishes are wired into CI behind flags but unproven, and nothing ran on real R36S, Android or iOS hardware.
- **Libraries that did not fit.** Arch.Persistence was incompatible with Arch 2.1 and not AOT-safe (the ECS wrote its own serializers); the managed Silk.NET OpenAL loader emitted AOT warnings (audio uses function pointers instead); Aether.Physics2D lost the benchmark to Box2D v3 by a factor of 23 and was removed.
- **Review noise.** CodeRabbit skipped the PR outright (892 files against a 100-file limit). Copilot's eight findings included one false positive (valid C# 12 syntax) and seven small but real improvements, all applied.

## Major wins

- **The whole plan shipped.** All stages 0 through 7, including 5b and 6b, landed in one branch that builds with zero warnings, passes 1,377 tests and publishes under NativeAOT with no engine warnings.
- **Performance targets met with zero allocation** in every hot path measured: 6 ns per sprite, 82 microseconds to extract 10k mesh entities, 53 microseconds for a 500-widget UI frame, 14.6 ms for a 10k-body physics step, 0.3 ms for a 10k-entity network snapshot round trip, 34 microseconds for an HTTP round trip on loopback, and desktop binaries of about 12 MB starting in under 100 ms.
- **Decisions backed by measurement.** Box2D v3 versus Aether was settled by a 10k-body benchmark on x64 and arm64 (including a rebuild without fused multiply-add for bit-identical results across architectures); Arch versus Friflo, direct calls versus delegate chains and the generator's inlining shape were all benchmarked before committing.
- **Codegen paid off.** Four Roslyn generators (schedule, events, queries, network serializers, plus web routing) removed reflection from the frame, kept NativeAOT clean, gave readable stack traces and 27 compile-time diagnostics.
- **Agentic development is real, not aspirational.** The `ion` CLI, an MCP server with 21 tools, a remote protocol with a proper access-control model, templates with `CLAUDE.md`, and an acceptance test in which an agent builds, runs, screenshots, inspects and mutates a game without reading engine source.
- **Parallel worktrees with disjoint scopes worked.** Twelve waves, at most four agents each, and merge conflicts were confined to the solution file, changelog, README and roadmap every time. A repeatable merge recipe (strip conflict markers, repair solution entries, build, test under Xvfb, push, remove worktree) kept the integration cost to minutes per wave.
- **CI hardening as a byproduct.** Driving the PR green exposed and fixed real portability bugs (the Silk.NET loader, the macOS listener) and left the test suite independent of line endings, file-system casing, thread-pool state and wall-clock timing.

## Quality of the final output

**Verified.** 1,377 tests across 35 assemblies pass on Linux, Windows and macOS; the Ubuntu lane also runs windowed Vulkan tests under Xvfb and golden-image comparisons on both Vulkan and OpenGL ES; the AOT lane publishes five samples with zero engine trim or AOT warnings and measures size and startup for linux-x64 and the R36S preset under QEMU; replay tests hash 10,000 physics steps and match across architectures; network convergence tests run a headless server and client over lossy loopback and real UDP.

**Documented.** Six design documents (rendering 3D, UI, physics, remote, web, networking), platform pages for publishing and the R36S, an agent workflow guide, a changelog with breaking changes called out, and a roadmap with "as implemented" notes per stage that record what deviated from the plan and why.

**Honest about gaps.** The PR description lists what is unverified (mobile and handheld hardware, cross-OS publishes), unstarted (WebSocket transport for networking, the browser target) and known to be wrong (the 2D ray cast returns sensor colliders). The smaller per-module gaps (tilemaps, parallel queries, streaming music, UI text selection, compound colliders, TLS, grid interest, scene-world replication, a virtual resolution for small screens) are in the roadmap.

**Risks a reviewer should weigh.** The branch is 921 files and 110k lines in one PR, which no automated reviewer covered in full and which a human cannot read end to end; the module-level design documents and the per-module test suites are the practical review surface. One breaking change to the public windowing API (`SilkWindow.View` now exposes a Silk.NET view rather than a window) is noted in the changelog. Nothing has been exercised on a physical device, and the 30 MB desktop and one-second handheld startup budgets are met only on the CI runner and under emulation.
