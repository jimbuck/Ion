# R36S and other Linux arm64 handhelds

The R36S (Rockchip RK3326, 4x Cortex-A35, Mali-G31 MP2, 640x480 panel, 1 GB RAM) runs ArkOS, an Ubuntu-based
linux-arm64 distribution with Mesa's Panfrost driver. Panfrost's OpenGL ES 3.1 is the stable graphics API there (PanVK,
the Vulkan driver, is experimental), so an Ion game on the R36S uses:

| Layer | Choice |
|---|---|
| Graphics | `Ion.Extensions.Graphics.GLES` (OpenGL ES 3.1, ES 3.0 fallbacks) |
| Windowing and input | `Ion.Extensions.Windowing.SilkNet` with the SDL platform (ArkOS ships SDL2 with KMSDRM; there is no X server) |
| Build | NativeAOT, `linux-arm64` |
| Window | fullscreen at the panel's 640x480 |

`GraphicsBackend.Auto` already prefers OpenGL ES on linux-arm64 (`GraphicsBackendSelector.AutoOrder`), so a game that
registers the backend-selecting graphics (`AddRhiGraphics`) picks GLES there and Vulkan on desktop without a separate
build. The `r36s` publishing preset below makes the choice explicit.

## Publishing: the r36s preset

```sh
python3 build/arm64-sysroot.py ~/sysroot-bionic-arm64        # once: Ubuntu 18.04's arm64 glibc 2.27 runtime
dotnet publish Ion.Examples/Ion.Examples.Breakout.ECS -p:IonTarget=r36s -p:IonArm64SysRoot=$HOME/sysroot-bionic-arm64
ion publish Ion.Examples/Ion.Examples.Breakout.ECS --target r36s --sysroot ~/sysroot-bionic-arm64   # the same
```

The preset (`build/Ion.Publish.props`, see [publishing.md](publishing.md)) is a NativeAOT `linux-arm64` publish (no
EventSource, invariant globalization, stripped symbols) plus:

- `appsettings.r36s.json` in the publish folder, unless the game ships its own:

  ```json
  {
    "Ion": {
      "Window": { "Platform": "Sdl", "Fullscreen": true, "Width": 640, "Height": 480, "ShowCursor": false },
      "Graphics": { "PreferredBackend": "OpenGLES", "VSync": true, "FramesInFlight": 2 }
    }
  }
  ```

  The launcher sets `DOTNET_ENVIRONMENT=r36s`, so the host's `appsettings.{Environment}.json` convention loads it over
  `appsettings.json`. The same settings work on the command line: `--Ion:Window:Platform=Sdl --Ion:Window:Fullscreen=true
  --Ion:Window:Width=640 --Ion:Window:Height=480 --Ion:Graphics:PreferredBackend=OpenGLES`.
  `Ion:Window:Fullscreen = true` is shorthand for `Ion:Window:WindowState = FullScreen`.
- The ArkOS SD card layout in `<publish dir>-arkos/` (`IonArkOSDir` to move it, `IonArkOSName` for the folder and script
  name):

  ```
  README.md                            installation notes
  ports/<name>.sh                      the launcher (Ports menu)
  ports/<name>/<executable>            plus libSDL2-2.0.so, libopenal.so, appsettings*.json and Assets/
  ```

  Copy `ports/` onto the card's ports folder (`/roms/ports`, or `/roms2/ports` with two cards) and restart
  EmulationStation. The launcher replaces the bundled `libSDL2-2.0.so` (a generic build without the device's video
  drivers) with the system SDL2, which ArkOS builds with KMSDRM and the device's controls (Silk.NET opens
  `libSDL2-2.0.so` next to the executable first; exFAT has no symbolic links, so it copies when linking fails), and
  writes the game's output to `<name>/log.txt`. `libglfw.so.3` (unused with SDL) and the `.dbg` symbols stay out. EGL and
  GLES come from the device's Mesa.

To check on a desktop what an ES 3.0-only device would run, add `--Ion:Graphics:Gles:MaxFeatureLevel=Es30` (or `Es31` for
the Mali-G31's level; desktop Mesa reports ES 3.2).

### Cross-compiling from linux-x64

NativeAOT cross-compiles with clang and lld (the preset sets `LinkerFlavor=lld`); the only extra input is an arm64
sysroot whose glibc is not newer than the device's (ArkOS is based on Ubuntu 19.10, glibc 2.30; .NET 10 needs glibc 2.27
or later). Host packages (Ubuntu/Debian): `clang lld zlib1g-dev python3 dpkg` for the build, `qemu-user-static` to run
the result. `build/arm64-sysroot.py` downloads Ubuntu 18.04's arm64 `libc6`, `libc6-dev`, `linux-libc-dev`,
`libgcc-7-dev`, `libgcc1`, `libstdc++-7-dev`, `libstdc++6`, `zlib1g` and `zlib1g-dev` from ports.ubuntu.com, extracts them
with `dpkg-deb -x` and makes their absolute symbolic links relative.

Without `IonArm64SysRoot`, the Ubuntu cross packages (`libc6-dev-arm64-cross`, `libgcc-13-dev-arm64-cross`) also link,
but the binary then needs the host's glibc (2.34 or later) and does not start on ArkOS; the preset warns (`IONPUB003`).
The restore downloads the arm64 runtime packs (`Microsoft.NETCore.App.Runtime.linux-arm64` and
`Microsoft.NETCore.App.Runtime.NativeAOT.linux-arm64`); the x64 ILCompiler compiles for arm64, so no arm64 .NET SDK is
needed. The same flags without the preset: `dotnet publish <game> -c Release -r linux-arm64 -p:PublishAot=true
-p:SysRoot=<sysroot> -p:LinkerFlavor=lld`.

### Running it under QEMU

```sh
cd <publish dir>
qemu-aarch64-static -L ~/sysroot-bionic-arm64 ./Ion.Examples.Breakout.ECS --Ion:Headless=true --Ion:Run:Frames=1
```

`-L` points the emulator's dynamic loader at the sysroot. Rendering under QEMU (EGL, llvmpipe) needs Ubuntu 18.04's
arm64 Mesa in the root as well (see the spike document's GLES section).

## What has been verified, and what has not

Verified (Stage 7, September 2026): Breakout ECS published with `-p:IonTarget=r36s` against the glibc 2.27 sysroot
(11.6 MB executable, `GLIBC_2.27` at most) runs headless under `qemu-aarch64-static` on an x64 host: 0.6 s from process
start to exit after one frame, median of 10 (emulated, so an upper bound unrelated to the Cortex-A35's speed;
[measurements](../plans/benchmarks/2026-09-stage7-publish/README.md)). The ArkOS layout (launcher, README, handheld
configuration) is produced by the publish and checked by `Ion.Tools.Tests.PublishProfileTests`.

Verified (September 2026, see the spike document's GLES section): the quad sample cross-published for linux-arm64 against
the glibc 2.27 sysroot (the executable needs `GLIBC_2.17` symbols at most) runs under `qemu-aarch64` with Ubuntu 18.04's
arm64 Mesa 20.0.8 (llvmpipe, OpenGL ES 3.1, the same level as Panfrost on the Mali-G31), headless through EGL, picks
OpenGL ES by `Auto` (the linux-arm64 order), and writes a frame identical to the x64 Vulkan and GLES goldens, at the ES
3.1 and ES 3.0 feature levels.

Not verified: real R36S hardware, the Panfrost driver, SDL's KMSDRM video driver, fullscreen at 640x480, gamepad input
through SDL on the device, the launcher on ArkOS, frame times and startup on the Cortex-A35. Breakout's play field is a
fixed 2030x984 layout in window coordinates, so at 640x480 it needs a scaled view (a virtual resolution in the 2D
renderer), which is not done.
