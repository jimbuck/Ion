# R36S and other Linux arm64 handhelds

The R36S (Rockchip RK3326, 4x Cortex-A35, Mali-G31 MP2, 640x480 panel, 1 GB RAM) runs ArkOS, an Ubuntu-based
linux-arm64 distribution with Mesa's Panfrost driver. Panfrost's OpenGL ES 3.1 is the stable graphics API there (PanVK,
the Vulkan driver, is experimental), so an Ion game on the R36S uses:

| Layer | Choice |
|---|---|
| Graphics | `Ion.Extensions.Graphics.GLES` (OpenGL ES 3.1, ES 3.0 fallbacks) |
| Windowing and input | `Ion.Extensions.Windowing.SilkNet` with the SDL platform (ArkOS ships SDL2 with KMSDRM; there is no X server) |
| Build | NativeAOT, `linux-arm64` |
| Window | fullscreen at the panel's 640x480 |

`GraphicsBackend.Auto` already prefers OpenGL ES on linux-arm64 (`GraphicsBackendSelector.AutoOrder`), so a game that
registers the backend-selecting graphics (`AddRhiGraphics`) picks GLES there and Vulkan on desktop without a separate
build. The profile below makes the choice explicit.

## Profile

`appsettings.r36s.json`, loaded on the device (for example with `--environment r36s` and the host's
`appsettings.{Environment}.json` convention, or copied over `appsettings.json` in the device build):

```json
{
  "Ion": {
    "Window": {
      "Platform": "Sdl",
      "Fullscreen": true,
      "Width": 640,
      "Height": 480,
      "ShowCursor": false
    },
    "Graphics": {
      "PreferredBackend": "OpenGLES",
      "VSync": true,
      "FramesInFlight": 2
    }
  }
}
```

`Ion:Window:Fullscreen = true` is shorthand for `Ion:Window:WindowState = FullScreen`. The same settings work on the
command line: `--Ion:Window:Platform=Sdl --Ion:Window:Fullscreen=true --Ion:Window:Width=640 --Ion:Window:Height=480
--Ion:Graphics:PreferredBackend=OpenGLES`.

To check on a desktop what an ES 3.0-only device would run, add `--Ion:Graphics:Gles:MaxFeatureLevel=Es30` (or `Es31` for
the Mali-G31's level; desktop Mesa reports ES 3.2).

## Publishing for linux-arm64

From a linux-x64 machine, NativeAOT cross-compiles with clang and lld; the only extra input is an arm64 sysroot whose
glibc is not newer than the device's (ArkOS is based on Ubuntu 19.10, glibc 2.30; .NET 10 needs glibc 2.27 or later):

```sh
# Ubuntu/Debian host: clang, lld, and an arm64 glibc 2.27 sysroot (Ubuntu 18.04 packages: libc6, libc6-dev,
# linux-libc-dev, libgcc-7-dev, libgcc1, libstdc++-7-dev, libstdc++6, zlib1g, zlib1g-dev from ports.ubuntu.com,
# extracted with dpkg-deb -x and with absolute symlinks made relative).
dotnet publish Ion.Examples/Ion.Examples.Quad -c Release -r linux-arm64 -p:PublishAot=true \
  -p:SysRoot=/path/to/sysroot-bionic-arm64 -p:LinkerFlavor=lld
```

Without `SysRoot`, the Ubuntu cross packages (`libc6-dev-arm64-cross`, `libgcc-13-dev-arm64-cross`) also link, but the
binary then needs glibc 2.34 (the host distribution's) and does not start on ArkOS. The restore downloads the arm64
runtime packs (`Microsoft.NETCore.App.Runtime.linux-arm64` and `Microsoft.NETCore.App.Runtime.NativeAOT.linux-arm64`); the
x64 ILCompiler compiles for arm64, so no arm64 .NET SDK is needed.

What to copy to the device: the executable, and in place of the bundled `libSDL2-2.0.so` (a generic build without the
device's video drivers) a symbolic link to the system SDL2, which ArkOS builds with KMSDRM and Mali support:
`ln -sf /usr/lib/aarch64-linux-gnu/libSDL2-2.0.so.0 libSDL2-2.0.so` (Silk.NET opens `libSDL2-2.0.so` next to the executable
first). `libglfw.so.3` is unused with SDL and can be left out. EGL and GLES come from the device's Mesa.

## What has been verified, and what has not

Verified (September 2026, see the spike document's GLES section): the quad sample cross-published for linux-arm64 against
the glibc 2.27 sysroot (the executable needs `GLIBC_2.17` symbols at most) runs under `qemu-aarch64` with Ubuntu 18.04's
arm64 Mesa 20.0.8 (llvmpipe, OpenGL ES 3.1, the same level as Panfrost on the Mali-G31), headless through EGL, picks
OpenGL ES by `Auto` (the linux-arm64 order), and writes a frame identical to the x64 Vulkan and GLES goldens, at the ES
3.1 and ES 3.0 feature levels.

Not verified: real R36S hardware, the Panfrost driver, SDL's KMSDRM video driver, fullscreen at 640x480, gamepad input
through SDL on the device, frame times and startup on the Cortex-A35.
